# 支持范围与验收状态

当前为 1.1.0a7 预览版。目标平台是 Windows 10/11 x64、64 位 Python 3.10+ 或便携版。
1.1.0a7 的组件安装包采用官方 HTTPS、固定哈希及发布者签名；安装结果仍需复检，3010 标记待重启。
OpenAL 与 PhysX 分开检测；PhysX 检查已部署的 x86 Loader，不能替代具体游戏的 SDK、GPU 和物理运算验收。
MSXML 4.0 仅为按需旧应用兼容组件，微软安全更新包也不表示其恢复支持；文件检测不等于 COM 功能或应用执行通过。
启动项管理只处理用户明确选择的 Run 注册表值，不结束当前程序；下一次登录才体现变化，不能据此证明开机速度提升。
VC++ 2002/2003、MFC/ATL 7.1 的应用本地依赖没有自动下载路径。尚不能声明 100% 替代，见 REPLACEMENT_MATRIX.md。
尚未验证 Windows ARM64、32 位解释器、Windows Server、多用户提权后的原用户 HKCU 映射。
1.1.0a6 的 VC++ 2005 x86 检测检查同一 WinSxS 程序集的身份清单及 CRT 文件架构，修正普通系统目录检测导致的安装后误报。
这是程序集文件清单验收，不模拟特定应用清单版本绑定、加载或执行；x64 不由这一项代替检测或安装。

1.1.0a5 双击 KSR.exe 不显示控制台，通过系统默认浏览器打开本地检测页；命令行改用 KSR-cli.exe。
无标准输出的图形入口会将启动信息写入本地日志，启动失败显示消息，不能用控制台存活代替图形启动成功。

1.1.0a4 的桌面窗口使用独立临时浏览器配置；本地服务通过已认证页面请求和 5 秒心跳维持，
不因 Edge 启动进程交接后退出而停止。窗口关闭后约两分钟无心跳才结束；休眠恢复后给予重连时间。
`--no-window` 和 `--browser` 模式仍可用 Ctrl+C 停止。没有修改用户常用 Edge 配置、代理或防火墙。

已验证：规则构建、沙箱扫描/修复/复检、PE 普通导入静态分析、应用私有 Qt 依赖识别、
运行时配置家族读取、文件与临时 HKCU 键撤销、用户后续修改冲突保护。
签名验证失败会阻止安装器执行；下载仅允许列出的官方 HTTPS 主机并限制重定向。

尚需在可回滚虚拟机及真实设备上验收：各代运行库安装成功/失败/重启，音频恢复测试音，
打印队列和测试页，多种 Windows 版本/语言、企业策略、离线或代理网络。
这些操作未作为本机自动测试执行。源代码测试通过不等于修复成功率已得到统计验证。

1.1.0a3 补充实测：真实下载和 SHA-512 校验、私有目录安装官方 .NET 8 Desktop/Core 运行时、
Windows 签名验证运行时宿主，以自建托管程序加载 WPF，注入 Desktop 框架缺失后启动失败、恢复后成功。
私有安装不更改系统 .NET，也不使普通应用宿主自动改用该目录；需通过该目录的 dotnet.exe 启动应用 DLL。
Windows Print to PDF 已生成有效测试页；网络打印提交调用曾超时，用户随后现场确认收到测试页、打印正常，没有重复提交。
音频端点、服务及低音量播放调用正常，重播后现场用户确认听到了清晰正常的声音。
音频播放和物理打印属于经用户确认的功能验收；没有在真实设备上人为破坏声卡/驱动或队列，不能据此证明全部故障修复能力。

撤销只覆盖通过本程序记录的注册表值、服务状态/启动类型及受支持的文件替换。
不能整体卸载运行库、撤销 regsvr32、恢复已删除的临时文件或打印任务、恢复被结束的进程。
新建注册表值撤销后可能保留空父键。中断、备份损坏或与当前状态冲突时会停止自动恢复。
服务触发器和系统策略可能再次改变状态。部分失败的撤销记录需人工检查。

诊断应用不会启动或加载目标文件。它检查普通直接导入和 .runtimeconfig.json，
未完整模拟延迟导入、递归依赖、SxS、PATH、插件、KnownDLL 优先级或自定义 .NET 宿主。
“尚未定位”表示需要进一步诊断，不是确认丢失。API Set 不按同名实体文件计为缺失。
默认全机 DLL 清单仅检查当前解释器架构，x86 应用请通过“诊断应用”单独检查。

现代 .NET 安装支持 x86/x64 稳定版、常规框架依赖部署和六种 rollForward 策略，
核对 Desktop/ASP.NET 对基础运行时的常规依赖，并读取 DOTNET_ROLL_FORWARD 覆盖。
仅自动选择微软元数据标记 active/maintenance 的通道中的当前稳定补丁；不安装 SDK、预发布版或已终止支持通道。
精确固定的旧补丁、旧 applyPatches/rollForwardOnNoCandidateFx、复杂依赖冲突会阻止自动处理。
存在自定义 DOTNET_ROOT 时，不根据系统目录宣称应用宿主已满足要求；需显式选择私有目录或另行诊断。
自包含程序不安装共享运行时；不修改原 runtimeconfig、不执行目标程序。
系统级安装需要管理员，校验官方 SHA-512 和 Microsoft 签名；私有 ZIP 安装只允许新目录并验证宿主签名。
安装后 verified 表示受支持的运行时配置复检通过，不保证任意应用可以运行；系统级 EXE 真实安装及重启尚未验收。
计划、下载、安装等错误会明确返回；安装器和整个新私有目录均不能由“撤销”整体卸载。

版本选择和安装参数依据微软文档：
[版本选择](https://learn.microsoft.com/en-us/dotnet/core/versions/selection)、
[Windows 安装](https://learn.microsoft.com/en-us/dotnet/core/install/windows)。

修复状态：verified=复检通过，failed=执行/复检失败，unverified=验证未完成，
pending_reboot=需要重启后重新检测，planned=仅预览。重启后的验证需用户重新扫描。
安装器动态返回的重启要求也会保留；多架构安装部分失败时，结果仍为失败，同时保留重启提示。
打印队列权限不足、目录丢失或其他读取错误均显示检测未完成，不计为通过，也不能据此清理。
已通过受控替身回归验证上述状态，尚未进行真实安装器与重启验收。
退出码：0=命令完成，2=修复失败，3=尚待验证。CLI 的 --json 输出尚非统一机器协议。

便携版尚无本项目发布者的代码签名。可通过公开源代码自行构建；下载后核对 SHA-256。
修复工具不能处理所有驱动、硬件损坏或系统无法启动的问题，也不承诺完整替代商业产品。
